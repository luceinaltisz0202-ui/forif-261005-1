[Git 커밋(Commit) 설명 문서]

1. 커밋(Commit)이란?
- 정의: 변경된 파일들의 상태를 특정 시점의 스냅샷(Snapshot)으로 저장소에 영구 기록하는 기본 작업 단위입니다.
- 개념: 단순히 파일을 저장하는 것(Save)을 넘어, 의미 있는 작업 단위의 변경 내역을 하나의 버전으로 확정 짓는 작업입니다.
- 특징:
  * 각 커밋은 고유한 40자리 해시 ID(SHA-1 체크섬)를 부여받습니다.
  * 커밋 작성자(Author), 작성 일시, 부모 커밋 정보, 변경 내역, 커밋 메시지가 함께 저장됩니다.
  * 커밋 기록을 통해 언제든지 이전 시점으로 되돌리거나(Checkout/Reset/Revert), 차이점을 비교(Diff)할 수 있습니다.

2. Git의 3단계 작업 공간과 커밋 과정
- 1단계: Working Directory (작업 디렉터리)
  * 사용자가 실제로 소스 코드를 생성하고 수정하는 로컬 폴더 공간
- 2단계: Staging Area (스테이징 영역 / Index)
  * 커밋할 파일들을 선별하여 등록하는 준비 공간 (버퍼 영역)
  * 명령어: git add <파일명> 또는 git add .
- 3단계: Repository (저장소 / .git)
  * 커밋이 데이터베이스에 영구적으로 기록되어 버전으로 보관되는 공간
  * 명령어: git commit -m "커밋메시지"

3. 커밋 관련 주요 명령어 및 옵션
- git status : 현재 수정된 파일 및 스테이징 상태 확인
- git add <파일명> : 특정 수정 파일을 스테이징 영역에 등록
- git add . : 수정 및 추가된 모든 변경 사항을 스테이징 영역에 등록
- git commit -m "<메시지>" : 스테이징된 파일들을 메시지와 함께 커밋
- git commit -a -m "<메시지>" : 이미 추적(Tracked) 중인 파일들을 한 번에 스테이징 및 커밋
- git commit --amend : 직전 커밋의 메시지를 수정하거나 누락된 변경 사항을 추가 병합
- git log --oneline : 커밋 이력을 한 줄씩 요약하여 조회
- git show <커밋ID> : 특정 커밋에서 변경된 세부 코드 차이(Diff) 확인

4. 좋은 커밋 메시지 작성 규칙 (Commit Convention)
- 원자적 커밋(Atomic Commit): 하나의 커밋에는 하나의 명확한 작업(기능 추가, 버그 수정 등)만 포함
- 기본 구조: <타입>: <제목>
  * feat     : 새로운 기능 추가
  * fix      : 버그 수정
  * docs     : 문서 수정 (README, 매뉴얼 등)
  * style    : 코드 서식, 세미콜론 누락 등 로직 변경 없는 스타일 변경
  * refactor : 코드 리팩토링 (기능 동작 변경 없이 구조 개선)
  * test     : 테스트 코드 추가 또는 보완
  * chore    : 빌드 스크립트 수정, 패키지 설정 등 유지보수 작업
- 제목 작성 요령:
  * 50자 내외로 간결하고 명확하게 작성
  * 개조식/명령조 문체 사용 및 끝에 마침표를 찍지 않음
- 본문 작성 (필요 시):
  * '어떻게'보다는 '무엇을', '왜' 변경했는지를 설명

5. 커밋 시 주의사항 및 모범 사례
- 빌드 오류나 문법 에러가 발생하는 불완전한 상태로 커밋하지 않기
- 보안 토큰, API 키, 데이터베이스 암호 등 민감 정보가 포함되지 않도록 주의 (.gitignore 사용)
- 의미 없는 대량 변경을 한 번에 커밋하지 않고, 작업 단위별로 잘게 쪼개어 커밋
