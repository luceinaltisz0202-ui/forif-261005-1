[깃허브(GitHub) 설명 문서]

1. Git과 GitHub의 차이점
- Git: 로컬 컴퓨터에서 소스 코드의 변경 이력(버전)을 기록하고 관리하는 분산 버전 관리 시스템(DVCS)입니다.
- GitHub: Git 저장소를 웹과 클라우드 환경에서 호스팅하여 백업, 공유, 협업을 가능하게 해주는 원격 플랫폼 서비스입니다.

2. 깃허브의 핵심 개념
- 저장소(Repository): 프로젝트 파일과 전체 커밋 기록이 보관되는 공간 (Local / Remote)
- 커밋(Commit): 코드 변경 내역을 저장하는 스냅샷 단위
- 브랜치(Branch): 독립적으로 작업을 분기하여 진행하는 가상의 작업 공간
- 이슈(Issue): 작업 할 일, 버그 제보, 기능 개선 아이디어를 관리하고 토론하는 공간
- 풀 리퀘스트(Pull Request, PR): 작성한 브랜치를 다른 브랜치에 병합(Merge)해 달라고 요청하고 코드 리뷰를 진행하는 프로세스

3. 기본 협업 워크플로우 (GitHub Flow)
- 1단계: 이슈(Issue) 생성하여 작업 목표 설정
- 2단계: 최신 main 브랜치 기반으로 새 작업 브랜치 생성 (git switch -c feature/...)
- 3단계: 파일 수정 및 커밋 (git add, git commit)
- 4단계: 원격 저장소로 브랜치 푸시 (git push origin feature/...)
- 5단계: GitHub 웹에서 Pull Request 생성 및 코드 리뷰 후 Merge
- 6단계: 로컬 main 브랜치 최신화 (git checkout main && git pull) 및 완료된 브랜치 정리

4. 주요 명령어 모음
- git status : 현재 작업 폴더 상태 확인
- git add <파일명> : 스테이징 영역에 파일 추가
- git commit -m "커밋메시지" : 변경 사항 저장
- git log --oneline : 커밋 이력 요약 확인
- git branch : 브랜치 목록 확인
- git switch <브랜치명> : 브랜치 이동
- git push origin <브랜치명> : 원격 저장소로 업로드
- git pull origin <브랜치명> : 원격 저장소의 최신 내용 동기화
